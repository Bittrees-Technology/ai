# Workflow hub synchronization

A paired local workflow device publishes an opaque saved-template and local investor-research index to the existing AI service every minute while the companion is running. No new device is registered automatically. The owner must complete the existing wallet pairing; unpaired or revoked devices cannot publish. Metadata synchronization grants no approval or execution scope.

Only workflow ID, revision, operation kind and bounded local state leave the device. Names, prompts, research briefs, URLs, model settings, local files, task input and output remain local. The hub shows generic process steps and the last device heartbeat. An offline device cannot report new changes until it reconnects. Removing a template publishes a tombstone on the next successful snapshot; revoking a device immediately hides or marks its workflow records removed at the source.

Cloud migration: apply `modules/remote/migrations/workflow-catalogue.sql` to the existing coordinator database. The workflow hub uses an independent read-only metadata function and applies current Roles permissions as well as owner filtering. The companion needs a build containing this change; updating the AI website alone cannot change an installed local app.

Investor research also publishes bounded numeric progress: this run's saved people and target, processed/queued pages, skips/failures, and separately checked dataset/confirmed CRM counts. Only a paired owner can read it through Workflows; names, briefs, URLs, candidate records and results stay at the source. The recorded measurement and CRM-check times remain visible when the Mac is offline. A source extension is confirmed in the local app, preserves the run ID and saved results, accepts only additional HTTPS sources within existing source/page limits, and stops against a freshly read dataset total target. It never changes qualification criteria, CRM permissions or execution approval.

A verification target is separate from a bounded additional research batch. Selecting an existing connected project requires its current qualification permission; the read-only qualification context supplies actual CRM verification labels. Only matching Qualified assessments with all six supported gates, a current Fully verified CRM label/category, and a mapped organization contribute, deduplicated by CRM record ID. The final completion audit still checks unique identities/aliases. A failed source refresh marks the previous numeric count unavailable and retains its actual check time; it never fabricates zero or verified progress. No labels are written by the sync worker.
