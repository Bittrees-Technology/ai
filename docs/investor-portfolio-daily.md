# Daily private investor research preparation

The native-only schedule origin is explicit (`scheduleOrigin: "native"`). Absent origin
retains the previous Codex migration behavior, including refusal to restart a previously
paused source. Native schedules require a separate `nativeReady` admission on enable,
every run and before source actions. No original Codex automation is fabricated or paused.
The injected native admission must verify the exact reviewed definition and a single
schedule owner, and deny a conflicting existing source schedule. The current launcher
provides no such admission for investor research, so the definition remains inactive.

`InvestorPortfolioDaily` prepares one reviewed candidate per bounded run. The operator
supplies a fixed candidate/alias/URL manifest and exactly eight dataset bindings named
`investor-portfolio-01` through `investor-portfolio-08`. It never reads a default connector
or exposes a project/task, sharing, publication, outreach or training operation. Every
private snapshot must identify the exact dataset and contain no linked CRM records.

Public reads require an injected trusted native adapter with exact approved HTTPS URLs,
TLS/DNS pinning, private-address rejection, robots/access handling and response bounds.
No fetch, shell command, credential lookup or ambient network fallback is installed here.
The local model callback must pin the reviewed local model and supply actual model/input
provenance. Returned facts are strict proposals: their URL, quote and value must match the
fresh exact source text. Unsupported data holds the run. Fund-size, financing-round and
LP-minimum figures have separate fields and cannot substitute for initial/follow-on cheques.
Business routes, conflicts, closed programmes and unknowns remain explicit in private
research descriptions; these are neither allocation authority nor workspace publication.

The encrypted journal uses WAL/FULL, guarded private paths and atomic compare-and-swap.
It binds the candidate queue, approved hosts, model profile and all dataset IDs. Draft
identity and cursor survive restart. Stable entry IDs and current aliases are checked
across all eight lists; ambiguous matches hold. Existing IDs/names/descriptions are
preserved, fresh versions and duplicates are checked again before a write, and unchanged
facts do not create repeated description blocks. Drafts expire after 24 hours. Current
workflow/source/cost authorization is required for every operation. Per-call timeouts and
caller cancellation bound native callbacks; timed-out source mutations remain pending.

Only one private append or enrichment may run per action. Its operation ID is durably
saved before dispatch. A source response alone is insufficient: a fresh read must confirm
the exact private entry. A dropped reply, abort, conflict or uncertain outcome is reconciled
through source reads and never blindly retried. Absent or changed entries remain held.
Separate owner review/publication is required for any CRM workspace change.

Startup registers only an inactive collector. Native source/keychain/model interfaces,
private-edit action wiring and native schedule admission are not provisioned by that
registration. Preparing or importing a definition is not verification, activation or a
scheduled execution receipt. The existing app, database and schedules remain untouched.
Before release/activation, verify actual staged native startup/sandbox behavior, exact
current source scope, local-model/MCP receipts and the first natural scheduled operation.
