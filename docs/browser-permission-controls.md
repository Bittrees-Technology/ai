# Browser task permission controls

The signed-in recovery/setup page mounts an explicit permission panel over the retained `BrowserTaskConsent` provider and verified host. The browser may prepare source-free tasks for a reviewed Mac and, separately, read its results. Both choices start unchecked. The Mac independently approves receiving, its local model and sharing results; the browser cannot select that model or grant sources, memories, tools or publication.

Refresh reads saved keys, public pins, device checks and permission metadata without granting authority. Review asks the host to validate the actual retained key, reviewed Mac and independently completed browser check. A one-hour, four-hour or one-day duration is capped by the current browser registration. Expiry changes access, not content retention. The returned original choices and public identity must match the displayed snapshot before an unchecked acknowledgement is shown. Confirmation compares that same saved snapshot again, then the host/backend atomically revalidates current authority and consumes the original one-use review.

Scope, registration/key/peer/check controls, leaving the window, Escape and wall/monotonic deadlines close reviews and discard pending output. A delayed response cannot restore the old review. No mutation is automatically retried. A failed final verification may follow a committed local write: refresh history to inspect the outcome before a new review. Unrelated status rendering does not alter the reviewed permission or check its acknowledgement.

Saved choices are displayed as history, not a live connection or current Mac consent. Replacing permission applies to new tasks; it does not reopen tasks/results tied to an earlier grant. Revocation cannot retract previously copied messages or cancel a task already admitted by the Mac. Offline owner-local revoke and delete require distinct reviewed actions and exact versions. Delete removes the saved permission ciphertext/key while retaining a minimal lock; reset requires a different verified browser registration and active key, and starts empty. Task history and independent exports remain separate.

An explicit JSON export contains public device details and permission metadata only. It contains no private keys, prompts, task output or encrypted task content, and cannot restore authority. Download URLs and visible reviews are cleared on concealment/teardown. Existing Bittrees typography, muted blue/green palette, bounded readable history and stacked phone layout are retained.

Disposable GitHub browser tests exercise the actual built page, SIWE/HTTPS/cookies/PostgreSQL, retained browser keys and actual Mac peer/check modules with synthetic storage/native slots. They cover independent choices, completed-proof requirements, original-review semantics, reload/export, cancellation, held verification, competing tabs, offline maintenance and post-commit uncertainty. Desktop/phone previews are retained for review. This is not personal browser/native or independent protocol acceptance.

Task composition, durable exact-message preparation/reconciliation, trusted host task dispatch, offline task-history maintenance and automatic encrypted transport remain open. No task form or network sender is added here. Browser common5, Mac task23 and remote8 are unchanged. Installed PR40, prepared PR142, model defaults, Acer-server's model/runtime/news jobs and live hosting remain unchanged. Mac inference has no Acer fallback.
