# Native agent setup and wallet draft review

The Mac app's **Agent setup…** menu opens a native four-stage panel: Identity, Wallet, Permissions review and Activation. It uses no web view, source session, wallet connection or automatic identity read. Identity inspection calls the existing separate native confirmation flow when its helper is available; only a successful key continuity review records local public identity context. Roles registration, current person/role and public Agent association remain unverified by this panel.

The wallet stage offers **Create a new agent Safe** and **Connect an existing Safe** as paths to review, with explicit unavailable status. Neither choice deploys/connects anything. A new Safe must use actual recovery owners/threshold, a reviewed Ethereum-mainnet factory/implementation plan and gas estimate, then explicit native wallet approval. It starts unfunded without autonomous authority. Existing Safe ownership/threshold also need authoritative verification. Identity can be established before a Safe exists.

Permissions review imports a regular JSON document of at most 128 KiB with exactly `current` and `proposed` fields. `current` is null for an initial review. The native shell passes bytes through stdin to a fixed, five-second, network-denied local subprocess. No file path, command, credential or signing capability is passed to that helper. It validates the policies, displays changed fields in side-by-side supplied-current/proposed columns, and preserves raw-unit budgets and exact calldata for inspection. All imported values, agent binding, wallet ownership and chain enforcement remain explicitly unverified.

The copied portable review module is from Agent commit `d4e97c10faf860b041cf0b2dfb32a2e1b68d8d5c`: SHA256 `24ca9b356f25d151493898c9c50e1b3b2a1e860a9c35a2b0f2dc851952a5ffb5`; its canonical dependency is `880637ce1d55ac606562c42843e6fca8ab90e96583381a2d3409c670ba8b1088`. The build verifies both hashes before copying runtime assets. The canonical agent ID is an enrolled Roles MCP principal, not a public Agent profile ID; schema validation does not establish actual enrollment or ownership.

Default duration is **Until revoked**. Amendments preserve the same agent, Safe, signer and period and require the next revision and previous policy digest; changed limits are compared without recreating authority. Pending amendments leave existing confirmed limits in force. Review never resets usage counters or tombstones, clears suspension, resumes expired authority or equates local suspension with onchain revocation.

Activation is disabled in this implementation. No adapter establishes source approval, Safe ownership, enforcement or chain confirmation. No transaction key is generated; the identity key remains dedicated to identity/pairing. No wallet sign-in, signature, deployment, gas payment, funding, permission grant, policy write or transaction is performed. Actual activation still needs current active-person Roles, exact source scope, separate native transaction-key approval, current Safe approval, verified enforcement/readback and explicit native activation. Appending a policy draft or selecting a wallet path cannot supply those facts.

Drafts and local inspection context are memory-only and cleared when this setup window closes. Cancelling a review cannot apply permissions. Failed/oversized/unknown-field/wrong-network/unsafe-scope documents are rejected without exposing their contents in error output. Releasing this UI requires the usual actual-head required checks; no installation is implied by local preview acceptance.
