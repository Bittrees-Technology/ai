# Hosted sign-in cancellation

The status page now maintains an authentication generation separately from its view epoch. Sign-out, wallet changes and session refresh publish an empty account/scope immediately, including during a wallet prompt or pending verification. Every asynchronous sign-in boundary checks that generation before proceeding or adopting a returned account. A wallet change away and back cannot pass by returning the same address. The accepted server account must have the expected chain, valid owner/address and an unexpired session; each accepted login/refresh gets a new local scope. `sessionContext()` also stops returning a scope after the observed expiry.

Ordinary blur and view concealment still clear displayed reviews but do not replace the authenticated scope. This permits wallet popups and later recovery-file selection. A future mounted browser-key host must use the authenticated context and invalidate immediately when it becomes empty or changes; the recovery entry point is not mounted by this change.

Sign-out remains available in the actual page while authentication is pending. It clears local access synchronously, waits for outstanding authentication responses, then clears the server session. New authentication is blocked until cleanup settles; repeated wallet changes share that cleanup. Unrelated status requests do not delay server sign-out, and their late errors cannot restore the old view. An unsuccessful server cleanup is reported and remains required before the next login or refresh. Post-verification login failure also cleans the possibly created session before allowing another attempt. A wallet prompt that never settles can delay server cleanup; local access stays cleared and no remote logout success is claimed.

The logout endpoint now accepts an absent session as already signed out and clears both session and login-challenge cookies. Present malformed or duplicate credentials still fail closed, and origin/HTTPS/request checks remain unchanged. This makes first-visit and repeated cleanup usable without interpreting a generic denied response as successful logout. It does not implement cross-tab login serialization: other tabs are still separate actors, and each protected browser-key operation verifies current server identity before and after use.

Verification includes deterministic delayed wallet/API boundaries and the actual shipped HTML, JavaScript, stylesheet and CSP on the closed CI HTTPS/PostgreSQL fixture. Browser tests cover late verification/session responses, clickable cancellation, wallet changes, normal prompt blur, failed logout cleanup and pending refresh with the browser's own cookie jar in Chromium, Firefox and WebKit. No test uses a personal wallet or public host. No schema, live deployment, installed app, Mac model or Acer runtime/news change is included.
