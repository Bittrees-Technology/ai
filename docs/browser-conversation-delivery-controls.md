# Reviewed browser conversation delivery

The saved-conversation view now connects retained messages to explicit relay sending and receiving. It uses one review surface for saving text, preparing an encrypted copy, uploading the original, stopping further uploads, receiving a selected queued message and reconciling a storage receipt for a selected outgoing copy. Existing file exchange, readable export and deletion remain separate actions.

Delivery history distinguishes a prepared copy, upload attempts, uncertain results, the last server observation and an authenticated Mac storage receipt. Preparing or saving does not upload. Relay storage does not imply recipient acceptance, reading or task completion. An incoming message uploads only its prepared storage receipt. Each review identifies the conversation, Mac/fingerprint and exact saved revision; outgoing send and receipt reconciliation reviews show the selected message text.

The host exposes bounded owner-local delivery metadata through `conversationContentAPI.deliveryHistory`. It decrypts only the current local owner's retained rows, returns no text, keys or envelopes, and rechecks the original rows after asynchronous decryption. It works without live identity/peer permission and supplies no authority to open or send content. This lets the owner inspect uncertain attempts after reload and review stopping an exact saved copy offline. Stopping retains history/content and cannot withdraw an already uploaded copy. Expiry ends delivery, not retention.

Incoming inspection displays one opaque transport selection and its expiry. Receiving and receipt reconciliation require separate confirmation and recheck the selected conversation and saved history. Changed or missing selections fail in the host. Missing parents stay queued; the view supports explicit navigation to the next item and restarting inspection from the beginning. Reconciliation binds the selected outgoing copy and cannot resend it. A failed/lost response directs the owner to refresh saved history before retrying.

All reviews use the existing focus, account/device, generation and bounded-lifetime fences. Opening another panel closes the current review. Cancelled/late responses do not restore private text or imply a successful delivery. Fresh consent/history and the exact selected revision are checked before action confirmation; online operations retain host key/peer/source checks. Offline history and stopping never renew authority.

The interface preserves the established typography, palette and two-column conversation layout, stacking on phones. It keeps native choices short and wraps complete identities in the review. The focused browser suite exercises the actual production build with synthetic relay/native peers: lost upload/reload/original retry, exact receipt matching, out-of-order parent navigation, receipt-only upload, offline history/stopping, focus/panel cancellation and a real worker question → browser answer → authenticated Mac HTTP → one continuation. A separate host scenario checks offline metadata and cross-account denial. Full regressions, individual desktop/phone screenshot review and disposable packaged Mac checks remain required.

No schema migration, Acer news/model/runtime change, model-default change, installed application replacement, personal data/key use or live activation is part of this package. Mac receive controls and full distributed/offline/recovery/personal/live acceptance remain separate work.
