# Saved browser relay confirmations

After an explicit task send, the verified browser host records the relay acknowledgement alongside the original encrypted outbox entry. Refresh, reload and owner-local export retain the last observed transport state. A newer failed handoff leaves the previous observation intact and appears as an unconfirmed attempt. The page continues to distinguish relay storage/destination acknowledgement from an authenticated Mac acceptance, task completion or reading.

The sender saves its attempt before network submission. Recording the response checks the exact message ID, envelope hash, retained ciphertext, response revision, owner and active transport scope. The short IndexedDB transaction rechecks the scope throughout its callbacks and commit. It cannot update a stopped, accepted, deleted, changed or locked entry. Older server revisions, changed storage timestamps and backwards transport states are rejected. A failed journal write returns uncertainty; a fresh reviewed retry uses the original ciphertext and server idempotency identity.

There is no public page API for submitting a claimed acknowledgement. The internal history callback is called only after the relay client validates the response. Stored history supplies no task permission, receipt-authentication authority or result-reading authority. The record contains bounded opaque routing metadata and times; task input/results remain encrypted and no credentials or key material are added.

Common browser database7 fences database6 writers. Opening the upgraded database does not rewrite existing keys, grants, preparations, envelopes or sequence counters, and does not backfill an acknowledgement for an old attempt. Existing task-history deletion removes this new field with its entry while preserving the shared sequence counters. Key-only recovery remains available independently of private outbox migration.

Five new cases run in each supported CI browser. They cover real relay delivery and reload/export/deletion, a lost later reply, an IndexedDB write failure followed by reconciliation, foreign/stale/regressing/invalidated receipt writes, and an actual pinned PR168 provider upgrade from common6. Shipped-page tests also check retained confirmation and unconfirmed retry messages. The CI browser job allowance is now 45 minutes: the prior 1,092-case integrated run used nearly the old 35-minute allowance, and this package adds both focused and full regression cases. Test assertions, retry policy and coverage are unchanged.

This package does not add automatic retries/polling, new task authority, conversation replies, approvals, task resume or live activation. The Mac runtime/model and Acer news processing are unchanged. Independent review, native/personal acceptance and final dependency/PR checks remain separate.
