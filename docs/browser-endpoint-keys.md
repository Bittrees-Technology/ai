# Browser endpoint key storage

Status: internal browser provider, imported only by the disposable browser fixture. The production remote page does not use it. No live pairing, private transport, permission or recovery interface is enabled. Mac task schema23 and browser ciphertext-outbox schema1 are unchanged. The separate endpoint-key database is now version2; the [durable browser lifecycle](browser-key-lifecycle.md) adds coordinated selection while preserving original slot records. Installed PR40, prepared PR142, Mac models and independent Acer news processing are unchanged.

`BrowserEndpointKeys` retains P-256 ECDH keys across browser reloads. A trusted host supplies a fixed local owner and a current verified account/device/credential/lease plus a separately selected key ID and epoch. It must durably choose fresh IDs and monotonically increasing epochs, retire old selections and require fresh registration after storage loss. The provider cannot derive authority from an invitation, a stored record or a request. `creationAllowed` is a trusted fresh-slot decision, never a user-supplied flag. The [durable coordinator](browser-key-lifecycle.md) now provides that internal selection/replacement/deletion layer and gates managed slots inside the provider transactions. Production identity/UI integration remains open.

## Creation and use

Creation requires an exact key ID/epoch and explicit confirmation. One strict IndexedDB transaction reserves the slot before any cryptography; concurrent tabs see the reservation and cannot generate again. A generation interrupted without saved handles leaves an incomplete attempt. An explicitly selected fresh slot is required. A lost acknowledgement after durable storage may reopen the original key. No overwrite, automatic regeneration or plaintext/volatile-storage fallback exists.

Creation requires a separate nonextractable AES-256-GCM wrapping key supplied from an explicitly user-held random recovery secret. The provider never stores that wrapping key. Endpoint key material is briefly exportable during generation, encrypted with a fresh random 96-bit IV and fixed versioned additional data, then round-tripped before publication. The retained private CryptoKey is imported nonextractable and saved through IndexedDB structured cloning; public bytes remain exportable for HPKE. Each read validates the complete binding, handle type, algorithm, usages, extractability, public bytes and actual private/public correspondence. A final durable read and current-authority check fence changes during cryptography. Repeated successful reads retain stable runtime handle identity for existing receipt consumers; returned pair containers cannot alter that cache. `invalidate()` must be called immediately on host identity, key or permission changes, including logout followed by the same login. Database version changes/closure also invalidate the provider.

Invitations contain only the existing strict public contract and full fingerprint, bound to one intended recipient and at most five minutes/current lease. The recipient must independently compare the complete fingerprint. Keys and invitations do not grant task, result, source or publication permission. Consumers must separately recheck current registration, peer pins and operation consent at use/commit. Returned handles cannot be recalled after revocation or deletion.

## Storage and deletion

`org.bittrees.ai.browser-endpoint-keys` has a `slots` store and the subsequent lifecycle store; slots are keyed by a domain-separated local-owner hash and key ID. A scope index enforces twenty lifetime slots per trusted local owner, including incomplete attempts and deletion markers. Quota failures fail closed; no history or key is silently pruned. Bindings/public metadata are ordinary local IndexedDB data, not encrypted task content. The slot contains nonextractable platform handles and an authenticated encrypted recovery kit. Plain PKCS8/JSON key material and the recovery wrapping key are not persisted. Owned plaintext buffers are wiped where practical; strings/runtime/OS copies cannot be guaranteed erased.

Explicit local deletion remains possible offline or after lease expiry using the trusted fixed local owner. One transaction removes both handles/public bytes and the encrypted kit while retaining the immutable identity/deletion marker. Previously exported recovery kits remain separate copies. A creator racing that deletion cannot publish a key, and stale tabs fail on their next provider read. Deletion is idempotent for a known slot and never creates unknown slots. It does not revoke other devices, remove remote copies or retract handles already returned to callers. Clearing all browser site data also removes safety markers; external fresh registration/reconciliation is then essential. IndexedDB persistence is not a guarantee against eviction, hostile local storage modification or browser rollback.

## Recovery and release requirements

`recovery` requires an explicit exact-key confirmation from the trusted fixed local owner and returns only the stored encrypted kit. This ciphertext-only export remains available offline after lease expiry, even if runtime handles cannot be used. A deleted slot cannot export its kit. `openBrowserKeyRecovery` authenticates that kit using the separately held recovery key and returns the original binding/public key plus nonextractable runtime handles. Wrong keys, changed format/IV/ciphertext, extra fields and invalid public/private correspondence fail without partial material. This is a recovery primitive, not restored authority: it never changes a selected slot, registration, consent, pins, sender sequences or replay history.

The internal [setup and backup controls](browser-key-controls.md) generate a cryptographically random recovery secret, require separate saved copies and verify the selected saved kit before activation through the durable coordinator. Before production activation, complete verified identity/fresh-registration integration, native/personal setup acceptance, historical decryption/rotation rules and a reviewed restore flow. Never use a password, account credential or local-storage key as the supplied wrapping key. The saved-item checker does not restore key history or authority; full restore and independent acceptance remain unfinished. The existing Mac local-storage recovery kit does not cover these browser keys. No personal keys are created by this internal provider.

Do not claim nonextractability protects against malicious code on the same origin: compromised code can use handles or read plaintext. Browser/client update trust, production consent integration, protected delivery, live transport, independent cryptographic review and personal browser/native acceptance remain open. No remote service is deployed by this change.

## Verification and specifications

The disposable GitHub suite exercises Chromium, Firefox and WebKit with real IndexedDB/WebCrypto: durable reload, encrypted-kit reopening and both HPKE directions, denied runtime private export, stable handle identity, exact confirmation/current owner/binding/lease, concurrent creators, interrupted generation, deletion races and stale tabs, offline owner isolation, quota failure, uncertain durable acknowledgement, late host invalidation/expiry, corrupted handles/identity/public bytes, capacity and version changes. The subsequent lifecycle and UI suites verify internal coordinated selection and saved-file setup. Synthetic fixture authority is not real sign-in or production identity integration. Three Node WebCrypto tests additionally cover actual recovered-key HPKE decryption, key/ciphertext/format/size denials and wrapping-key requirements. Local browser automation is not used.

[WebCrypto serialization](https://www.w3.org/TR/webcrypto/#cryptokey-interface) specifies CryptoKey persistence through structured cloning and preservation of usage/extractability properties. [IndexedDB transactions](https://www.w3.org/TR/IndexedDB/) define transaction scope, completion/abort and version-change behavior. These platform mechanisms do not supply application authorization or protect a compromised endpoint.
