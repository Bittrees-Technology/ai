# Memory term coverage and feedback lineage

The former ranking combined full-text retrieval with a substring coverage calculation. For `art report`, the record `quarterly report` could claim both terms because `quarterly` contains `art`. Conversely, `café deadline` could match an accent-normalized query but claim only half its coverage. Coverage now comes from individual FTS queries against the same ephemeral index used for retrieval; the response includes matched query terms. [SQLite documents the default Unicode61 tokenizer and normalization behavior](https://www.sqlite.org/fts5.html#unicode61_tokenizer). Search still means lexical matching, not semantic relevance, truth, translation or certainty. It does not add stemming, synonym matching or embeddings.

Current permission, expiry and review filtering still precede indexing. The index remains an in-memory SQLite connection closed after each search; no persistent plaintext index is added. At most20 distinct query spellings,1,000 owner memories and20 returned results are considered. Repeated query spellings are deduplicated; different spellings normalized to the same token are still distinct query terms. Exact-text deduplication, source diversity within equal-coverage groups, source-access rechecks and late-change fencing remain in place. Search does not generate feedback or select memory for a task.

Memory schema2 adds a nullable keyed content fingerprint to each feedback record. New ratings bind to the exact encrypted memory input (text, type, origin, sources and expiry). Ranking counts only ratings with the current fingerprint. Pinning or approval changes do not change that fingerprint; changing the wording/provenance/expiry does. Returning to the exact former content may reuse its earlier ratings. Prior ratings are retained rather than deleted. Legacy schema1 feedback has no proven content association: it stays in the database and encrypted backups with a null fingerprint and contributes zero to ranking. A new rating must use a new feedback ID; legacy IDs are not silently rebound.

The local feedback endpoint now requires the current memory `revision` alongside `id` and `outcome`. Missing revision is invalid, stale revisions conflict, and a feedback ID cannot change either its outcome or content binding. Current source access, post-await revision and expiry checks remain mandatory. Same-content exact retries are idempotent. Feedback remains a bounded self-reported ranking signal; this change does not establish verified facts, run-bound usefulness, protection against a person inventing multiple rating IDs, or automatic model self-evaluation.

Migration1→2 is transactional and preserves records, pins, approval state and every legacy rating. Older memory engines reject schema2; rollback requires an original schema1 backup restored separately. Task schema20/browser1/import1 are unchanged. Content is retained until explicit deletion; no model/default, permission, source grant, hosting or Acer processing changes are made.

Run `npx tsx scripts/memory-ranking-check.ts` for the synthetic comparison. Six manually labeled two-term queries cover substring distractors, numeric boundaries and accent matching. The prior PR133 implementation reports6/12 coverage values correctly and ranks the full match first in0/6 cases; current code reports12/12 and6/6. After a content correction, the former implementation carries a0.2 usefulness score forward; current code reports0 while preserving the old rating. [Recorded comparison](evidence/memory-ranking-2026-09-23.json) retains both outputs and exact source hashes. These narrow lexical measurements do not establish general retrieval quality, real-source or native/personal acceptance.
