# Temporary model import files

The companion releases its UUID-named staging directory after a durably recorded installation, cancellation or non-installation failure. It keeps the encrypted import record, exact file hashes, license/repository/revision, review and verified installation metadata. It never removes original picker files or calls Ollama to uninstall models. This is temporary-file cleanup, separate from the user's retention of task content and memory.

Startup and one-minute idle maintenance also release interrupted pre-installation work, retry unfinished cleanup and expire unused download/installation reviews. Active work holds the same coordinator reservation as cleanup. Shutdown waits for an in-flight cleanup. A still-valid review keeps its files; an installing/reconciling job interrupted by restart becomes uncertain and keeps all reconciliation files. Neither maintenance nor cleanup downloads, creates, retries or reconciles a model. Unknown directories without a job record are left alone.

Cleanup first persists a pending marker, then removes only the job directory, then records released status. A filesystem failure records retry status without changing the import outcome or exposing raw paths/errors. An interrupted final write leaves pending status; removal is idempotent after restart. If the pending write fails, removal does not start. Import-history deletion remains a separate confirmed action. The additive encrypted job field retains database version 1; older clients ignore it, while installed/terminal states cannot restart installation.

Models explains the lifecycle and exposes an explicit retry on cleanup failure. The authenticated `POST /v1/imports/:id/cleanup` accepts only an empty body and an existing UUID job. It rejects live reviews, active work and uncertain installations; it cannot accept a filesystem path. Existing install/reconcile controls remain separate. A failed request is not automatically repeated by the browser; trusted idle maintenance may retry cleanup only.

Tests use synthetic GGUF files, disposable databases, simulated loopback model responses and injected filesystem/database failures. They verify original files and symlink targets survive, provenance remains encrypted, cleanup serialization and shutdown, recovery after removal but before a completion write, expiry, uncertain/live-review preservation, authentication and no repeated runtime actions. Browser CI checks keyboard retry, failed cleanup, retained history and narrow/desktop rendering. This does not constitute real-model compatibility, native-picker or personal-device acceptance. Installed app/models, personal data, Acer-server model/runtime/news jobs and hosted services remain unchanged during development.
