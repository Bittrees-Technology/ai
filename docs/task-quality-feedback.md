# Human review of a model result

Tasks offers Used as-is, Needed edits and Not useful, an optional 2,000-character note and explicit confirmation that the user reviewed the result. These map to accepted/edited/rejected quality outcomes. They do not publish content, approve a connector action, establish factual truth, train a model or automatically promote a model/prompt. A self-reported review is evidence for later evaluation, not independent quality acceptance. The note can describe corrections; it does not replace the draft text.

A review belongs to the exact completed task revision, result fingerprint and last completed recorded model run. Failed, queued or unrecorded results cannot be rated. The stored run retains its actual profile/digest and any existing prompt/provenance fields. Displayed duration is the whole recorded run, including preparation/source checks, not a pure inference benchmark. Recording a review does not change task revisions, model history, memory approval, source permissions or publication receipts.

Only the latest review per result is stored and exported. Revision checks reject concurrent/stale changes. An exact retry of the latest operation returns the same record without adding votes. A changed payload with that operation ID is rejected. Deletion writes a content-free review tombstone with a monotonic revision, preventing a stale form from recreating deleted feedback. Task-data deletion cascades to the review. Review notes and binding metadata use the existing encrypted task store and backup controls.

The authenticated local GET/PUT `/v1/requests/:id/quality-review` rechecks source access before reading or changing a connected-app review and rereads the task after the asynchronous check. The request supplies the expected task/run/review revisions, an operation UUID, the review or null, and explicit confirmation. It accepts no caller authority fields. Ordinary bulk JSON export includes only local source-free reviews. Connected-source reviews appear only in the per-task export with current source permission. Revocation conceals stored reviews; it cannot retract copies already displayed or exported.

The interface clears notes on focus loss, validates access every 15 seconds while visible, suppresses stale reads and late responses, preserves input on an uncertain save and never automatically retries a write. A fresh server revision replaces stale editing state. Saved reviews remain until explicitly deleted; previous replaced review text is not retained as a separate voting history.

Task schema 20 adds the encrypted review table. Existing task/model data is preserved. [Compatibility evidence](evidence/task-feedback-schema-compatibility-2026-09-23.json) uses the actual signed, extracted PR128 engine and bundled Node: schema19 seed/backup → current schema20 preservation → review backup/restore → old engine refuses20 → original19 backup restored separately. Rollback does not carry forward new reviews. InstalledPR40/preparedPR128 remain unchanged; neither contains this feature.

Verification covers owner/tenant separation, strict inputs, repeated operations, revision conflicts, failed transactional writes, deletion, encrypted storage/backup, source denial and deletion during delayed access checks. Browser CI covers explicit keyboard confirmation, uncertain exact retries, stale reads, source-denial concealment, focus loss and desktop/narrow layouts. No new real-model generation, source pilot, independent quality judgment or personal/native acceptance is claimed.
