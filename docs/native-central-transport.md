# Bounded native central workflow transport

`CentralTransportPlan`, `CentralNativeHTTPS`, `CentralTransportBudget`, `CentralNativeBroker` and `CentralNativeClient` prepare the native transport for a bounded central-worker verification. They are **unregistered**: the launcher and model core do not construct them, no production review exists, and importing them performs no network requests.

The trusted native owner must bind a reviewed device principal/public key, credential digest, delegation, tenant, workspace, workflow and source connection. Every request must carry the matching fresh Ed25519 Roles proof, exact canonical parameter digest and logical operation ID. Only `workflow_claim`, `workflow_renew` and `workflow_complete` can reach the fixed MCP endpoint. The gateway still verifies current Roles and source authority on every action; native review never grants either authority.

The HTTPS adapter validates and pins public IPv4 DNS answers, retains TLS hostname/certificate validation, refuses redirects and encoded/non-JSON replies, and bounds request/response bytes and deadlines. It uses a native-owned MCP credential; model-supplied bearer credentials are not part of its input. A changed, expired or revoked local review denies before dispatch and after DNS/response completion. The model sandbox remains unchanged.

Before DNS, every attempt consumes a durable encrypted budget reservation. Failed or uncertain calls retain their full reservation. A repeated proof request ID is rejected; a fresh proof for the same logical operation consumes another attempt. Reservations survive restart and a changed review cannot reset an already used epoch. At most 108 attempts and one hour are admitted. Included usage requires independently verified zero-cost evidence. A one-time spending review is limited to $1 and must supply an independently established **aggregate downstream upper bound per attempt**, not a guessed average price. An evidence identifier or approval file alone proves neither cost nor source authorization.

The authenticated loopback broker/client accepts only the fixed central action envelope, rejects browser Origin/Cookie requests and mismatched Host/capabilities, and admits one action at a time. The core-side fetch adapter drops model-side bearer credentials and has no remote fallback. It is not yet constructed by the app.

Still required before registration: trusted credential/identity bootstrap, native action-time consent with exact scope/cost evidence, current signed Roles/source permissions, and live completion/successor/revocation evidence. These one-hour verification primitives do not establish a standing until-revoked production transport or migrate a schedule. No live source calls or grants were created during their local fixture tests.


`CentralNativeService` now assembles a separate native control capability and core execution broker. Proposal and approval compare the complete immutable wallet/scope/budget digest. A session opens only after exact current approval; no credential provider runs while proposing or opening a session. `nativeCentralSessionFactory` constructs the real HTTPS adapter and durable encrypted budget only under current source/cost admission. Revocation denies immediately, aborts work and drains it before closing storage. Failed storage close holds future approvals while both local ports are still closed.

These assemblies remain unregistered. Trusted launcher identity/credential reading, the native review display and core environment wiring, current source/price evidence, standing until-revoked runtime support and actual live acceptance are still required. A bounded verification review is separate from a standing Roles delegation. No production review, grant or source request has been created.
