# Bounded native central workflow connection

The optional native launcher, approval screen and fixed MCP transport are prepared for a bounded central-worker verification. **No production configuration/evidence has been written, no grant has been created, and this connection has not been installed or verified against live sources.** This bounded runtime does not complete standing until-revoked execution or migrate a schedule.

## Native bootstrap and consent

The existing parent helper launcher calls `launchCentral`. Missing `native-central.json` returns before Keychain access, sockets or source requests. Invalid configuration holds the central connection while preserving NAS, storage and the free-only OpenRouter broker. Configured use requires owner-only canonical regular configuration/evidence files, a current bounded evidence period naming the exact existing account/project/plan/services and aggregate per-attempt cost/overage controls, immutable file digests, and matching existing encrypted central identity/configuration/credential hashes.

The read-only SQLite accessor validates the existing Ed25519 key pair, never creates or rotates keys, and returns no private key or bearer credential in its public bindings. Source credential retrieval remains a separate native provider, invoked only for an admitted dispatch. Source/profile/credential changes invalidate the binding; ordinary local pause/resume does not change it.

`CentralNativeService` owns separate native-control and core-execution capabilities. A proposal opens no execution session. Exact approval binds the complete immutable wallet, workflow/device scope and cost budget. The Swift screen independently checks the Node canonical digest, exact fields, Ed25519 key/digest, matching scope/budget epoch and deadlines, and the $1/108-attempt maximum. Its default is Cancel. Only the core execution capability crosses into the engine; native control stays in the shell. Missing native capabilities preserve the existing worker path. Helper failure never falls back to direct remote execution.

Revocation denies immediately, aborts active requests and drains them before closing encrypted state. Failed storage close holds future approvals while both helper ports still close. Restart requires fresh native approval; it cannot reset a used budget epoch or extend its deadline.

## Fixed transport and durable budget

Every claim, renewal or completion must carry the matching fresh Ed25519 Roles proof, exact canonical parameter digest and logical operation ID. Only `workflow_claim`, `workflow_renew` and `workflow_complete` can reach the fixed MCP endpoint. The gateway must still verify current Roles and source authority for every action. Native approval and operator configuration grant neither authority.

The HTTPS adapter validates and pins public IPv4 DNS answers, retains TLS hostname/certificate validation, refuses redirects and encoded/non-JSON replies, and bounds bytes and deadlines. It uses a native-owned MCP credential. The authenticated loopback broker/client rejects browser Origin/Cookie requests and mismatched Host/capabilities, permits one action at a time and drops the core-side bearer credential. Changed, expired or revoked reviews deny before dispatch and after DNS/response completion. The model sandbox remains unchanged.

Before DNS, every attempt consumes a durable encrypted budget reservation. Failed or uncertain calls retain their full worst-case reservation. Repeated proof request IDs are rejected; a fresh proof for the same logical operation consumes another attempt. At most 108 attempts and one hour are admitted. Included usage requires independently verified zero-cost evidence. A one-time spending review is limited to $1 and requires an independently established **aggregate downstream upper bound per attempt**, not an average price.

Operator-written evidence or an evidence identifier is not a billing guarantee or Roles/source grant. The operator must independently verify the actual account, downstream resource ceilings and enforced controls before recording it. Configuration cannot authorize paid model fallback or bypass wallet/controller signatures.

## Remaining acceptance

Current independent source/price evidence, production configuration and exact native plus wallet/source approvals remain required. Staged native startup and sandbox boundaries must pass before installation. Live acceptance must demonstrate central trigger, genuine local-model execution, MCP/source action receipts, central completion and authorized successor, plus denial after revocation. Standing until-revoked runtime and actual recurring migration acceptance remain incomplete.
